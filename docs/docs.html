Forge Docs

Everything about Forge: installing it, the commands at the prompt, how failover works, approvals, skills, team mode, the sandbox, GitHub, MCP servers, and every setting.

#What it looks like

What you see Meaning

● Write · ● Update · ● Shell every file change and command, with a preview, a coloured diff, or the first lines of output
◆ Forge's reply, followed by who answered, how long it took and how many tokens it used

In a terminal without sixel graphics (anything older than Windows Terminal 1.22, or not WezTerm), the art is drawn with half-block characters instead.

When a step is risky, Forge stops and asks:

┌─ ? Delete C:\Users\you\projects\site\old ─────────────────────────────────┐
│ needs your OK: deletes files                                              │
└───────────────────────────────────────────────────────────────────────────┘
  Allow? yes · always for this kind · no ›

/exit prints how to get back: forge -c continues the conversation in that folder, and forge -r <id> opens it from anywhere.

#Install

Way Command
pipx (recommended) pipx install forgecommandline
pip python -m pip install forgecommandline
Windows exe, no Python download forge-vX.Y.Z-windows-x64.zip from Releases, unzip, put forge.exe on your PATH
From source python -m pip install . in this folder, or run forge.cmd directly

The command is forge whichever way you install it.

Updates. Forge checks PyPI once a day in the background and shows update 0.8.2 → 0.9.0 is out on the start screen when there's a newer version. Nothing installs by itself: type /update (or run forge --update) to install it — it picks pipx upgrade or pip install --upgrade to match how you installed. On Windows Forge closes and the update finishes in a new window; your conversation is saved, so forge -c picks it up. /update check only checks. The .exe build points you to the new zip on Releases. Turn the daily check off with FORGE_UPDATE_CHECK=0.

#First run

forge

The first interactive launch opens /setup, which adds a provider key. You can also paste a key straight into the chat (Forge recognises it, files it under the right provider and redacts it before anything is sent or saved) or use /keys add.

Forge doesn't come with keys of its own: it runs on yours. Free-tier keys from Groq, NVIDIA, OpenRouter, Cerebras or Gemini are enough to start, and every extra key or provider you add is one more place to fail over to. (A few public keyless gateways, kilo, llm7 and ovh, sit at the very end of the chain as a last resort; they are slow and rate limited, so don't rely on them.)

forge                         chat in the current folder
forge -c                      continue the last conversation here
forge -r [#|id]               pick a saved conversation, or jump to one
forge "fix the failing test"  one prompt, then exit
forge -m qwen/qwen3-32b       use a model for this run (or -m groq:qwen/qwen3-32b)
forge -p openrouter           use only one provider for this run
forge -t                      start in team mode
forge -y                      auto-approve everything (careful)
forge -v                      show the key rotation and failover log
forge --status | --sessions | --version

#How failover works

 your request
      │
      ▼
 ┌─────────┐ 429  ┌─────────┐ timeout ┌────────────┐      ┌──────────────────┐
 │  groq   │─────▶│ nvidia  │────────▶│ openrouter │─ … ─▶│ kilo · llm7 · ovh│
 └─────────┘      └─────────┘         └────────────┘      └──────────────────┘
  up to 4 keys each, the strongest available model first
  • Providers are tried in FORGE_PROVIDERS order, up to 4 keys each.
  • A rate limit rests only that model on that key (60 s for per-minute limits, until UTC midnight for daily ones, 1 h for 401/403). The same key keeps serving the provider's other models.
  • A provider silent for 30 s (FORGE_TIMEOUT) is skipped and avoided for a while.
  • Empty, junk or moderation replies count as failures; replies cut off at the token limit are continued.
  • The model that starts a task keeps it. If it has to hand over, the next model gets a note saying what is done and what is still open.
  • If every model is resting, Forge waits for the first one back (up to FORGE_MAX_WAIT, 150 s) instead of giving up.
  • A model that says the conversation is too large is remembered; Forge stops sending it conversations that big and trims old tool output if nothing else fits.

Models are ranked by a 1–10 capability score worked out automatically from the model's name, a quick background check and its track record. /roster shows each score and why.

#Features

#Approvals

what runs on its own and what asks

Mode Behaviour
smart (default) edits inside the folder and ordinary commands run; deleting, moving, git push/reset, global installs, registry, killing processes, admin, piping downloads into a shell and writing outside the folder ask
ask every change asks
auto nothing asks (forge -y)

FORGE_DENY_TOOLS (comma-separated names or globs) and FORGE_DENY_COMMANDS (semicolon-separated regexes) block actions even in auto mode.

#Skills

10 built in, 30 in the library, plus any Claude Code skills you have

A skill is a Markdown file of instructions:

~/.forge/skills/<name>/SKILL.md      yours, every project
./.forge/skills/<name>/SKILL.md      this project only

---
name: lint
description: Run the linter and fix what it reports
---
Run `ruff check .`, fix each issue, and run it again until it passes.
  • Built in: commit, debug, explain, init, review, run, security-review, simplify, skill-inspector, test, web-build. skill-inspector is adapted from NVIDIA SkillSpector (Apache-2.0): it scans a skill with skillspector scan --no-llm when that is installed, reads the source, and gives an APPROVE / CAUTION / REJECT verdict before you install it.
  • skills/library: 30 engineering skills (TDD, debugging, code review, planning, API design, security, CI/CD, performance, system design…). Third-party skills are MIT-licensed; see skills/library/LICENSES.
  • If Claude Code is installed, its skills are copied once into ~/.forge/library; /skills sync refreshes the copy.
  • Only Forge's own skills are listed to the model. It finds the rest with find_skill, so each request stays small. /skill new <name> creates one.

#Parallel agents and team mode

/parallel fix the test in api/ || write docs for utils.py || list every TODO in src/

Each task gets its own agent with a copy of the conversation, starting at a different provider. Reports come back into the main conversation. /parallel on lets Forge split work by itself; at most FORGE_MAX_AGENTS (5) run at once. With FORGE_WORKTREES=1 each agent works in its own git worktree under .forge/worktrees/ on a forge/agent-N-<time> branch; merge what you want.

/team on (or forge -t) adds a coordinator: it does small requests itself and splits bigger ones between the models that suit each part, then gives you one answer saying who did what. /roster bench measures every model; /team lead <worker> picks the coordinator.

#Docker sandbox

FORGE_SANDBOX=docker runs the model's shell commands in a container that only sees the project folder (mounted at /work). Dev-server ports are published on 127.0.0.1 only. FORGE_SANDBOX_NET=none cuts the network; FORGE_SANDBOX_IMAGE picks the image (default node:22-bookworm). Needs Docker Desktop running. Approval rules still apply.

#GitHub

  • /github login shows a code to enter at github.com/login/device and keeps the token in your key store; /github logout removes it. gh auth login or a token added with /keys also work.
  • The github_request tool covers repos, branches, issues, pull requests, Actions and releases. Reads are automatic, writes follow the approval mode, destructive operations always ask.
  • .github/workflows/forge-issue.yml: comment /forge on an issue (owner, members and collaborators only) and Forge works on a branch and opens a pull request.

#MCP servers and HTTP APIs

Forge reads MCP servers from ~/.claude.json (read-only), ~/.forge/mcp.json and the project's .mcp.json. Servers start only when a request needs them; tools load on demand with mcp_search. Stdio and streamable HTTP are supported.

{
  "mcpServers": {
    "my-service": {
      "type": "streamable-http",
      "url": "https://api.example.test/mcp",
      "headers": {"Authorization": "Bearer {{env:MY_SERVICE_TOKEN}}"}
    }
  }
}

http_request handles methods, headers, JSON/form bodies, uploads, downloads and pagination. Credentials written as {{env:NAME}} are filled in at send time and redacted from replies. openapi_import loads an OpenAPI 3 spec; openapi_search pulls in only the operations needed.

#Checks after every edit

.py, .json and JavaScript (including inline page scripts) are syntax-checked right after a write; a failure goes straight back to the model. browser_check opens a localhost page, reports console errors and saves a screenshot to ~/.forge/screenshots. When a turn builds a page or starts a server, Forge opens it in your browser (FORGE_AUTO_OPEN=0 to stop).

#Memory, hooks and project commands

  • FORGE.md, CLAUDE.md or AGENTS.md in the project are read automatically; /skill init writes one.
  • Notes saved with memory live in ~/.forge/memory/, per project or shared; /memory shows them.
  • .forge/commands/<name>.md becomes /<name>, with $ARGUMENTS for what you type after it.
  • Hooks live only in ~/.forge/hooks.json (never in a repo): pre_tool hooks get JSON on stdin and can block a tool with a non-zero exit; post_tool hooks run after. Argv arrays, no shell, 5-second timeout.

#Cost and limits

/cost shows what this session's tokens would cost per model; free tiers show as free and unknown prices say so. Correct prices in ~/.forge/prices.json: {"openai:gpt-4o-mini": [0.15, 0.6]} (dollars per million input, output tokens). /balance shows requests and tokens left per provider, and OpenRouter credits.

#The courier and the pixel city

Instead of a spinner, a pixel-art courier pushes a wheelbarrow of parcels along the status line, following real events: loading while the model thinks, waiting at the glowing door while a tool runs, dimmed during rate limits, a green door when done, spilled parcels when it fails. In sixel terminals (Windows Terminal 1.22+, WezTerm) it is drawn in real pixels; elsewhere in half-blocks.

/city on (or FORGE_SCENE=city) adds a pixel city above the message box where tiger-cub workers act out the same events. /city calm stills the motion, /city off hides it. FORGE_COURIER=off, FORGE_MOTION=reduce, FORGE_GRAPHICS=sixel|blocks|plain.

#Sponsor line

off unless a server is configured

One optional faint line under the working status, shown only after a task has run a few seconds — this is how Forge stays free. It is never shown in the first 7 days, in CI, for one-shot prompts, or when output is piped. The request carries only the Forge version, a random install id (/ads reset makes a new one) and which line was last shown — no prompts, code, file names or keys. It also counts the install as used that day, including in the first week (no line is shown then). Lines are signed by the server and stripped of escape codes; links go through the server so clicks are counted. /ads off or FORGE_ADS=0 turns all of it off; Forge works the same either way. Details in PRIVACY.md.

#Keys, privacy and where things are stored

  • Keys are read only from Forge's own .env, ~/.forge/.env or its key store, never from the project you are working in. The OS keychain is used when available (FORGE_KEYRING=0 to opt out).
  • Pasted keys are redacted before the model call, the saved session and input history. Logs show only the last 4 characters.
Path Holds
~/.forge/sessions/ conversations, saved after every turn
~/.forge/config.json chosen models and provider
~/.forge/keys.json keys when no keychain is available
~/.forge/state.json · usage.json key rests and health, keyed by one-way hashes
~/.forge/library/ Forge's copy of Claude Code skills
~/.forge/history your typed input, keys redacted

You are responsible for following each provider's terms for the keys you add.
